# ai.diy — Development handoff

## Product and stack

ai.diy is a local-first, BYOK chat workspace with 26 provider integrations. PrismiumLite is the legacy repository/storage name, not the product name.

- React Router 8 SSR, React 19, TypeScript, Vite 8, Tailwind 4.
- assistant-ui 0.15 and Vercel AI SDK 7; IndexedDB through `idb`.
- Use Node 22.22.2 or newer Node 22 LTS, or Node 24. The test dependencies do not support Node 23.
- `~/*` resolves to `app/*`. Browser-specific helpers use `.client.ts`; relay/provider code lives in `app/lib/server/`.
- `/` is the landing page; `/workspace` is the chat application.

## Run and verify

```bash
npm ci
npm run dev -- --host localhost --port 5173
```

The dev composer is supported again. The former input-reset bug was reproduced in an isolated assistant-ui harness: StrictMode caused store updates to stop reaching the controlled input. The matched core/store/react/tap patch set fixes the subscription lifecycle. Keep `tests/unit/composer.test.tsx` and dev E2E checks when updating these dependencies. Do not disable StrictMode or add a second draft state as a workaround.

A separate cold-start failure came from late Vite dependency discovery returning 504s for outdated optimized module URLs before hydration. `vite.config.ts` now scans the root, workspace routes, and lazy OpenUI registration up front. Dev E2E forces cache re-optimization with Vite’s `--force` and rejects stale-dependency responses/uncaught page errors; it must not rely on a warm cache.

```bash
npm run typecheck
npm run smoke
npm test
npm run lint:changed
npm run format:check
npm run build
npm run test:e2e
npm run test:e2e:dev
```

Playwright starts the production server at localhost:3000, or the dev server at localhost:5173 for `test:e2e:dev`, and a loopback-only mock OpenAI-compatible provider on port 18765. It seeds isolated browser contexts, needs no real key, and shuts its servers down automatically. Run `npx playwright install chromium` once locally. Do not point these tests at a running personal workspace.

CI runs typecheck, all 17 smoke scripts, unit tests, changed-file lint/format checks, build, production E2E, and focused dev composer tests. Existing hook/accessibility lint errors in touched legacy files are baselined; new errors fail. Formatting is checked on touched supported files, excluding the generated lockfile. Set `CHECK_BASE=<commit>` to check a committed change locally.

## Architecture and invariants

- `app/components/assistant-ui/AssistantRuntimeProvider.tsx`: AI SDK chat session, assistant-ui runtime, tool execution, transport, provider/model selection.
- `app/routes/api.chat.ts`: stateless model/tool relay; credentials arrive per request. Do not log bodies or keys.
- `app/components/assistant-ui/ChatThreadSync.tsx` and `app/lib/chat-store.ts`: history hydration, idle persistence, artifact extraction.
- `app/lib/db.ts`: database `prismium-lite-db`, version 14. Keep the name and `prismium-lite:*` settings keys unless an explicit migration is approved.
- `app/lib/tool-access.ts`: capability defaults and normalization. Enforce tool gates on both client and server.
- OpenUI is lazy-loaded, on by default, and can be disabled in tool access. Forwarded tools have bounded schemas and no server executors; they cannot shadow server tools. Supplemental instructions append to the base prompt.
- Generative UI has two tools under the one Generative UI switch: `present_openui` (plans, photos, maps, forms; `app/components/generative-ui/`) and `present_jsonrender` (dashboards, metrics, tables, charts; json-render, Apache-2.0, `generative-ui/json/`). `present_jsonrender` takes `patches`, an array of strings with one JSON Patch operation each (`/root`, then `/elements/<key>`), and renders finished elements while the call streams; old saved chats with a single `spec` string still render. json-render only accepts catalog components; `parseJsonRenderPatches` / `parseJsonRenderSpec` rebuild the spec and validate each component's props themselves because `catalog.validate` checks structure and type names only. Only add/replace/remove on `/root` and `/elements/<key>` are honoured (state, visibility, repeat and every action but `ask` are dropped). Tabs and Disclosure keep their open state locally in React, not in json-render state. Python charts (`run_python` + `savefig`) show inline via `RichFigure`/`Figure`, read locally from the thread's Canvas artifacts. Photos and maps need the External photos and maps switch; nothing else makes third-party requests.
- Interactive json-render cards are data only (`generative-ui/json/state.ts`, `present.tsx`, `scene.tsx`): a spec may declare flat primitive `state` (`/state` patch, max 40 keys), `Slider` / `Toggle` / `Select` write a named value, and any number, string or boolean prop may read it as `{"$state":"/name"}`. `validateProps` checks each component's schema with a typed placeholder in each expression's place, then restores the expressions; `$cond`, `$computed`, `$bindState`, nested paths and enum positions are rejected, and every bound name must exist once the call finishes. `Scene3D` draws up to 60 primitive parts with `three` (MIT, loaded on demand, orbit by drag, zoom off so page scroll is not hijacked) and shows a text fallback without WebGL. Button actions are `ask` and `reset` only. Card state lives in one `createStateStore` per card, so streamed-in values never overwrite what the user moved. json cards use the app theme tokens (`--color-foreground`, ...), not `--openui-*`, which are light-mode values outside an OpenUI theme.
- Adaptive skills (`app/lib/skills/assistant-skills.ts`, `app/components/assistant-ui/skill-tools.tsx`): `find_skill` / `use_skill` / `save_skill` are browser-executed frontend tools gated by the Skills switch (server drops them in `frontendToolsFromBody`). They are registered with per-tool `useAssistantTool`, not a second `Tools()` provider, because a nested `Tools()` replaces the tool-UI scope and hides the OpenUI/json-render cards. Only a fixed list of client tools resumes the run on its own, so `skill-tools.tsx` sends the follow-up itself once the results are in. Assistant-saved skills have an `assistant_` id, never overwrite user or built-in skills, are capped (25 skills, 20k chars), keep http(s) sources only, and render a visible card with Remove. `MAX_MODEL_INSTRUCTIONS_CHARS` is now 70,000 (OpenUI + json-render ~62k, skills up to ~5k).
- Card actions (follow-ups, Add, ask buttons) are locked while a reply runs (`ThreadBusyContext`); `JSONUIProvider` registers handlers once, so read changing values through refs.
- The scoped OpenUI/Zustand override is intentional. Plain `npm ci` must keep working; do not replace strict peer validation with `--legacy-peer-deps`.
- Settings is one `SettingsDialog` mounted by the workspace route and driven by `app/lib/sidebar-panel.ts` (an external store), not by route state: the sidebar mounts twice below `md`, and toggling route state re-rendered the whole shell. `useSettings` updaters return the previous state when a patch changes nothing, so a section re-asserting its toggles on mount causes no re-render or encrypted write.
- ChatGPT subscription: every OpenAI call has a deadline (`app/lib/server/chatgpt-fetch.ts`; `/responses` is bounded only until headers arrive and keeps the caller's abort for the whole stream; token refreshes are never retried because refresh tokens rotate). The client (`ChatGPTSessionProvider`) bounds its own requests, ignores results from a cancelled sign-in via a generation counter, and never lets the clipboard block the flow. ChatGPT gates the account's model list on the Codex `client_version` the server reports (`DEFAULT_LWC_CLIENT_VERSION` in `app/lib/server/chatgpt-client-version.ts`); raise the default when newer models stop appearing. `LWC_CLIENT_VERSION` can only raise it, because a value below the default (older `.env.example` files suggested 0.147.0) just hides models. `scripts/chatgpt-model-gate-smoke.mjs` proves the real path surfaces GPT-6.x against a fake OpenAI that applies that gate. A model is only auto-selected from the account's live catalog, never from the bundled fallback list.
- Web search: the model has no built-in `web_search` tool. Live search is Parallel Search or Firecrawl (the bundled keyless MCP servers, `FREE_SEARCH_MCP_PRESETS`) or, when the user enables one with their own key, a BYOK connector (`tavily_search`, `brave_search`, `exa_search`, `parallel_search`), which replaces the two MCP servers. The bundled servers load on every request while web search is on (`selectMcpServersForRequest`), not only when the wording looks like research, are connected in parallel with a bounded tool-list wait, and are owned by Web search access rather than MCP access (`mcpServersForRequest`, `toolAccessKeyForTool`; the server enforces the same split and also loads them for model previews). `fetch_url` is only added when they did not load. If search is on but nothing could load, the per-turn tools reminder says so instead of letting the model improvise. `frontendToolsFromBody` drops a client-supplied `web_search` so it cannot be brought back. `webSearchEngine` / `searxngUrl` stay in settings for storage compatibility but no longer drive any model-facing tool; `/api/search` is a standalone endpoint, not a model tool.
- Two interfaces (`settings.interfaceMode`, `app/lib/types.ts`): `simple` is a single sign-in screen (`SetupGate`, `simpleFlow`: ChatGPT recommended, OpenRouter, and "Use an API key" which opens the full steps) and a minimal input bar (`Composer` / `SimpleComposerFooter` in `Thread.tsx`: attach, input, send, a quiet model picker and "Full view"; no presets, mic, token chips, or provider picker; chat list collapsed). `full` is the original workspace and its composer is untouched. New installs get `simple`; settings saved before the field existed (`setupComplete` already true) load as `full` (`mergeLoadedSettings`), so nobody's interface changes under them. Settings → Appearance switches either way. The simple setup auto-continues once the ChatGPT account's live models are known; its sign-in has no confirmation dialog because the same disclosure sits next to the button (`ChatGPTHeroConnect`).
- Settings responsiveness: the dialog opens with a skeleton and the panel mounts one deferred render later (`useDeferredValue` in `SettingsDialog`); section switches render through `useDeferredValue(section)` so the nav responds first; the nav (`SettingsNav`, native `title` instead of 17 tooltips) and header (`SettingsHeader`) are memoized and read only what they show; the Settings backdrop has no blur (`overlayClassName`). With 12k messages, a 200-message chat open and a 4x CPU throttle, section switches dropped from 140-270 ms to 55-105 ms with almost no long tasks. The Linux runtime prefetch is idle-time so toggling it is not a long task.
- The simple composer is a tall pill (plus menu, input, mic, send) with the model and reasoning-effort chips underneath (`SimpleComposerFooter`); a lost ChatGPT session shows an inline Reconnect notice (`SimpleReconnectNotice`), and on a host that cannot keep ChatGPT sign-ins (`ephemeral`) the setup screen recommends OpenRouter instead. The landing hero preview (`HeroWorkspace`) mirrors the real workspace chrome (sidebar tabs, header, rounded composer, Canvas) but stays scripted sample data.
- Continue with OpenRouter (`app/lib/openrouter-oauth.client.ts`, `OpenRouterConnect.tsx`): OAuth PKCE entirely in the browser (S256 verifier kept in `sessionStorage`, one-time code exchanged at `https://openrouter.ai/api/v1/auth/keys`, key stored like a pasted key). No ai.diy server involvement, so there is no session to expire and nothing to host. `OpenRouterReturn` is mounted on the workspace route above the setup gate and only acts on a `?code` that this tab asked for. It has been tested against mocks only; the live exchange needs one manual run.
- ChatGPT sign-in options: the shipped flow is the Codex device-code flow through `@opencoredev/loginwithchatgpt-*` (works for hosted deployments, server-held session, not an official OpenAI integration). OpenAI now documents an official "Sign in with ChatGPT" for open-source and locally run apps (developers.openai.com/siwc: PKCE on a `127.0.0.1` loopback callback, a per-installation host ID, dynamic client registration, `chatgpt.tokens.use.direct` scope for plan usage). It cannot work from a hosted origin, and its SDK is not on npm, so adopting it for localhost/self-hosted installs is a separate task that needs the spec read in full.
- The landing page (`/`) is the public/SEO surface only. Visitors who already opened the workspace in this browser are sent to `/workspace` before first paint (`app/lib/landing-redirect.ts`); `/?landing` and arrivals from another ai.diy page still show it.
- `SectionBoundary` isolates message, Canvas, Settings, and OpenUI rendering failures. Copied diagnostics intentionally omit raw error messages to protect conversation data and keys.
- `storage-notices.ts` exposes persistence failures through a banner and toast. Failed chat saves retain an exportable in-memory snapshot and offer retry. Artifact failures keep the Canvas copy; oversized artifacts explicitly prompt download.
- Auto-memory indexing (`indexChatMemories` in `ChatThreadSync.tsx`) is gated by `settings.memoryEnabled`; disabling memory stops new entries but never deletes stored ones.
- Rendered markdown is sanitized (`app/lib/markdown-sanitize.ts`): `rehype-raw` output passes a `rehype-sanitize` schema (scripts/iframes/styles/forms/event handlers stripped, `href` limited to http/https/mailto) before `rehype-katex`. Remote `http(s)` images render as click-to-load placeholders (`markdown-image.tsx`) so a model-emitted `<img src>` cannot leak conversation data to a remote host; `data:`/`blob:` sources render directly via `markdownUrlTransform`.
- `MessageUsageStats` is wired into the assistant message footer and shows provider/model, token totals, and catalog-derived cost when the metadata exists.
- Persistent storage is requested best-effort on first use. Import & Export shows site-wide usage/quota estimates and allows a manual persistence request. This is not a backup guarantee.
- The squared visual system is retained, with `.legacy-round` preserving the original chat/composer shape.

## Known gaps and next milestone

1. Branches are not durable: `replaceThreadMessages` still removes messages outside the active path. Tier 1 must coordinate transactional incremental persistence, stable timestamps/parents, active-leaf state, assistant-ui history restoration, and export. No schema migration is included in Tier 0.
2. A pre-existing version-17 database cannot be opened by version-14 code. Errors now surface instead of leaving an unexplained loading screen. Never clear user data as a fix; use a compatible build or explicit backup/recovery.
3. The send path is still behind setup. Explore-before-setup remains a later milestone.
4. Real-provider behavior, Safari, full mobile accessibility, Python/VM execution, and real-model OpenUI output are not covered; the mock only streams canned `present_openui` programs.
5. Search/palette, shortcut changes, richer code blocks, and sidebar organization remain Tier 1; no additional providers/tools should precede them.
6. Existing large modules and legacy accessibility findings remain. Do not mix their broad refactors into a focused bug fix.
